# Research decisions against success criteria — Cycle 133

A research question is easier to act on when the final judgment explains what would
count as success. This release connects Define's success criteria to Deliver's
selected alternative, evaluations and source evidence. Failed or unknown criteria
must identify a next research action. A report is still a record of research judgment,
not independent proof that an experiment was valid.

## Example

```sh
python3 -m dd_research_runtime.criteria_demo --keep /path/to/new-example-directory
```

The synthetic example asks whether an explanation fits its context and transfers to
another one. Both criteria remain unknown. The saved research draft names the next
observations to gather; it does not manufacture support or recommend the explanation.
The example retains the Double Diamond learning loop, separate framing approval,
original phase visits, synthetic labels, checkpoints and pending publication.

## New cases

Use type start_criteria_research with the same workflow_id, brief, scope, questions,
max_alternatives and max_visits fields described in DOUBLE_DIAMOND_GUIDE.md. This
creates workflow_version=3. All four phases and their human-gated iteration rules
remain in place. Changing any defined framing or success criteria needs exact
material_reframing approval, and downstream work must be revisited.

Version 1 and 2 cases keep their original commands and historical report hashes.
There is no silent upgrade of an existing case or reinterpretation of prior approvals.
The current source also restores an unmodified checkpoint generated by Cycle 132.
Use the current reader/writer for new version 3 cases.

## Assess each defined criterion

A version 3 Deliver record additionally requires criterion_assessments. Cover every
current Define success criterion exactly once. Each assessment has:

- criterion_index: the zero-based position in the current success_criteria list.
- outcome: met, not_met or unknown.
- evaluation_ids: distinct IDs from the Deliver record. They must evaluate the selected
  alternative, rather than another option.
- rationale: a nonblank explanation of the judgment.
- next_research: a nonblank action for failed/unknown criteria; may be empty when met.

met needs a linked supported evaluation with evidence. not_met needs a linked
unsupported evaluation with evidence. unknown can explicitly have no linked evaluation,
with the gap and next action explained. Evidence/outcome consistency is checked, but
weighing conflicting results and interpreting what they imply remain human research
judgments. One evaluation can inform multiple criteria when its rationale supports that;
this does not make those assessments independent observations.

recommend requires every criterion to be met, in addition to recorded support for the
selected alternative. Otherwise use revise and return to earlier research, or stop_unresolved
with a clear limitation. The tool does not set arbitrary automatic scores or declare a
criterion true from a source ID. Synthetic comparisons retain their synthetic origin
and cannot satisfy real-source host acceptance.

## Trace the decision

The saved report's decision_trace expands criterion positions to the actual criterion
text and includes outcomes, explanations, evaluation IDs, evidence IDs, evidence origins
and next research. Markdown renders a readable 'Decision against success criteria'
section. Deliver's version binding includes the Define frame and Develop alternatives;
old assessments cannot silently apply to a newly framed question or reordered criteria.

Ordinary authorization, revision checks, idempotent retry, journal replay, crash recovery,
exclusive export and checkpoint rules apply. No external action is taken by a research
recommendation. Actual source acquisition, study quality, experiment validity and human
acceptance remain host responsibilities. The graphical interface remains unfinished.
